# C++ 流式重建类平面专项测评报告

日期：2026-08-07

测试对象：`setc/build_live_observer/Release/omnivggt_stream_server.exe`

测试主题：类平面表面上的 C++ 流式重建精度、速度、资源占用和历史一致性

## 一、摘要

本次测试在 TUM Photometric Depth Super-Resolution 数据集的 blanket 类平面表面上进行。正文以动态 bucket 为主方案，以固定 `pair-letterbox` 为备选方案。两种方案使用相同的 5 帧类平面回放和相同的精度评价口径。

| 评价维度 | 动态 bucket 主方案 | 固定 pair-letterbox 备选方案 | 结果分析 |
|---|---:|---:|---|
| 完整 5 帧吞吐 | 1.148 FPS | 0.968 FPS | 动态方案提升约 18.6% |
| 后续模型执行帧平均总耗时 | 1,381.687 ms | 2,095.615 ms | 动态方案降低约 34.1% |
| 后续模型平均耗时 | 1,037.469 ms | 1,743.749 ms | 动态 ROI 已传递到 C++ pair 推理 |
| 三维点到点 RMSE | 181.2 mm | 182.5 mm | 精度基本一致 |
| 三维 RMSE / 参考平均深度 | 3.00% | 3.02% | 动态输入没有造成精度退化 |
| 参考深度 AbsRel | 2.410% | 2.405% | 两种方案处于同一误差水平 |
| δ < 1.05 | 92.14% | 91.30% | 动态方案略优 |
| δ < 1.10 / δ < 1.25 | 100.00% / 100.00% | 100.00% / 100.00% | 两种方案均保持稳定相对深度一致性 |
| GPU 峰值 | 7,454 MiB（91.4%） | 7,801 MiB（95.7%） | 动态方案显存余量更好 |
| C++ 进程工作集峰值 | 3,917.6 MB | 1,824.1 MB | 固定方案主机内存更低 |

总体结果表明，动态方案已经完成从 Python 动态 ROI 逻辑到 C++ TorchScript pair 路径的有效迁移。它在保持点云精度的同时获得了更高吞吐和更低 GPU 峰值；固定方案则作为输入形状固定、部署简单、主机内存较低的可靠备选。

## 二、测试背景和项目改进目标

针对沙面、织物、墙面等连续缓变表面，现有通用流程容易出现多帧融合重影或分层、逐帧深度尺度不一致、边界拼接接缝、遮挡和删点造成孔洞、黑边误判为表面边界，以及每帧完整推理导致重复计算严重等问题。本项目的类平面流式链路针对性地解决这些问题，重点评价连续表面保持、局部更新和变化不足时的跳帧效果。

实现细节已经在项目的其他设计和代码文档中说明，本报告不重复展开方法过程，只记录结果和结果分析。动态方案用于验证 ROI 动态尺寸是否降低 C++ pair 推理开销；固定方案用于提供可直接回退的固定输入基线。

## 三、测试数据和基本口径

测试使用 TUM Photometric Depth Super-Resolution 数据集的 `xtion_blanket_sf2_sfs` 子场景，数据来源为 [TUM Photometric Depth Super-Resolution 数据页](https://cvg.cit.tum.de/data/datasets/photometricdepthsr)。本次仅使用约 15.1 MB 的 `xtion_blanket_sf2_sfs.zip`，没有下载大型完整序列。该表面具有纹理和连续缓变起伏，适合类平面专项测试，但不是数学意义上的无限平面。

## 六、论文使用限制

本次序列是由一张真实类平面表面图像经过已知单应变换生成的 5 帧回放，结果主要说明类平面配准、局部更新、动态推理、融合和跳帧链路的工作状态。由于 `z_est` 是 reference surface 而不是独立测量真值，当前精度结果适合作为相对表面一致性和方案对比结果。若论文需要绝对 Chamfer、绝对点到面误差或真实尺度法向误差，应进一步使用带独立测量真值的多序列进行验证。

当前样本量适合专项工程验证，但不足以支撑跨场景统计结论。正式论文可在多个纹理、倾角、运动幅度和真实连续帧上重复测试，并补充 mean±std、P50/P90、跳帧率、模型执行率和资源峰值。动态方案当前显存峰值约占 8 GB 的 91.4%，固定方案约占 95.7%；提高分辨率或增加动态 bucket 前应重新进行显存预算。

## 八、结论

本次类平面专项测试证明，动态 bucket 是当前 C++ 流式重建的更优默认方案：它在保持与固定方案相近点云精度的同时，提高了完整流式吞吐，显著降低了后续模型和整体执行时间，并降低了 GPU 峰值占用。固定 `pair-letterbox` 方案作为输入形状固定、部署简单的备选路径仍然有效。两种方案均已完成同一类平面序列上的精度、速度、资源和历史一致性验证，可根据部署条件选择使用。

## 已知问题与风险

### 当前代码为什么必然容易得到“长方形贴图”

`inference_pipeline.cpp` 约 4460 行的诊断分支遍历整个 canvas，只要任一 `group.valid_warp` 有效就创建 `z=0` 点，且重叠区始终优先使用 anchor 颜色。当前有效支持接近整张透视变换图像，因此联合结果天然接近矩形；anchor 中被机械臂遮挡的位置仍保留机械臂纹理，不会被侧相机地面替换。这正好解释了“范围仍为长方形”和“机械臂贴在平面上”。

随后代码用 anchor 深度相对稳健逆深度平面的残差提取高度，并把候选与 `bright_nonplanar_mask` 相交，再把高度点塞入未使用 slot。该方法会漏掉暗色机械臂，也没有从其它视角建立一致的三维物体表面；此前实拍中出现了与平面分离的大量错误散点。

### 已尝试但失败的方法

1. **恢复/移植本地六文件或历史融合版。** 多次尝试把本地正确流程移到工控机，因 GUI 流协议、真实相机分组、参数和运行环境差异，结果出现无输出、连接失败或视觉结果仍不正确。用户明确要求后续不要再做盲目整套移植，应在当前工控机代码上修。
2. **直接显示 B1S3 模型 shared-world XYZ。** 用于排除后处理影响；实际 GUI 是厚矩形板/三层图像片，证明模型原始位姿/深度在当前实拍输入下不能直接作为最终融合结果。
3. **调整三相机顺序和启动相位。** 试过由实际输入识别得到的 `[3,1,2]`、校准标签顺序 `[1,2,3]`，以及按位姿旋转方向修正的 `[1,3,2]`。最后一种使预测相对旋转符号接近 `data1` 标定，但点云仍是厚板。当前硬编码 modulo 映射仍不可靠。
4. **输入 Gamma/亮度修正。** `gamma=0.55` 只让厚板更亮，没有改善几何，已撤销。
5. **固定标定位姿回投影。** 将 B1S3 深度结合 `data1` 固定四元数/平移并按基线缩放，GUI 仍是厚矩形板，说明仅替换外参不足。
6. **平衡 RANSAC/平面感知融合。** 能压平部分地面，但真实场景下曾产生长方形范围、遮挡空洞、散点和高度丢失；单靠全局平面拟合无法同时解决多视图遮挡和机械臂高度。
7. **二维单应 floor-union。** 三路图像的 SIFT 单应本身能得到旋转的多边形覆盖，并显示出中央圆形结构；但实现使用近乎全图的 `valid_warp`，且 anchor 垄断重叠区，最终仍是矩形图像拼贴，也不会补机械臂下面的真实地面。
8. **逆深度平面残差恢复高度。** 第一版高度方向错误且形成大片平面下方散点；反转 Z 并加亮结构/连通域过滤后会丢失暗色机械臂，尚未得到通过 GUI 验证的连续高度。
9. **逐帧动态单应/全量画布更新。** 视觉上出现整体点云重新构建和跳动；没有完成固定标定或稳定滤波方案。

### 组帧风险

曾确认某次同步抓取的模型输入对应 GUI 三台海康相机且一次 forward 为 S=3，不是 `123、234` 滑窗。但物理相机槽位目前由 `source_seq % 3` 推断，GUI 或工控机重启后初始序号相位可能变化。下一实现应使用协议中的明确相机 ID 加时间戳/组号，不应继续依赖 modulo 猜测。
